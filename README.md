# 銀行洗錢防制（AML）異常交易預警系統建置歷程與技術決策 (POC)
2026-04 完成並已上線交易監控系統使用
以下有透過AI整理開發過程及指標選擇，無內部營運資訊

---

## 1. 專案背景與業務痛點

歷時約 1 年的專案推動中，主要挑戰並非模型算法的複雜度，而是**「極端不平衡數據特性」與「第一線調查量能固定」之間的衝突**：

* **數據極度稀疏：** 
  合法交易佔 99.9% 以上，真正經人工排查確認為高風險或需申報可疑交易（STR）的標籤比例極低（陽性率 < 0.05%），傳統分類指標（如 Accuracy、ROC-AUC）完全失真。
* **前線調查量能硬性限制：** 
  審查人員每日可人工調閱傳票與排查的案量上限固定（僅能消化前 0.5% 的高風險警報）。若單純追求高召回率（Recall）導致警報量暴增，前線調查人員將陷入警報疲勞。
* **黑盒子與稽核要求：** 
  模型不能只輸出一個分數，必須能向法遵人員與內部稽核解釋「觸發原因與特徵歸因依據」，否則無法替代傳統規則。

## 2. 端到端實作階段與思考歷程 (Phase-by-Phase Execution)

### Phase 1：需求訪談與指標收斂
* 與法遵及前線審查團隊訪談，確認業務痛點在於「傳統靜態門檻規則產生過多無效警報，佔據 70% 調查人力」。
* **架構決策：** 放棄追求純離線 ROC-AUC，將專案核心驗證指標定錨在 **「固定每日調查量能上限下（Top-0.5%），模型能捕獲的真實高風險案件比例（Top-K Capture Rate）」** 與 **PR-AUC**。

### Phase 2：特徵工程與冷熱特徵切分
* 透過 SQL 與 Polars 建立多維度時序聚合指標（1d, 7d, 30d 交易頻率、資金滯留時間、流動對手集中度比率等）。
* **踩坑與取捨：** 
  初期衍生了 100+ 個特徵，但在跨期驗證（OOT）時發現部分高度依賴「特定跨月統計」的特徵衰退極快（產生 Data Drift）。後續利用 SHAP 值與族群穩定度指標進行剪枝，將特徵精煉至穩定度最高的 10 餘個核心行為特徵，確保生產環境穩定。

### Phase 3：模型建置與極端不平衡策略演進
在極端少樣本下，嘗試了不同的處理手段，演進歷程如下：

1. **嘗試 SMOTE / 過抽樣（大失敗）：**
   * *實作嘗試：* 使用 SMOTE 在少數類別周圍合成虛擬樣本以平衡類別比。
   * *實測結果：* 離線訓練集評分看似提升，但推到跨期測試集時，**False Alarm 暴增近 40%**。
   * *根本原因：* 在高維稀疏空間且陽性樣本極少的情況下，K-NN 插值容易在多數類別的「雜訊邊界」生成錯誤的異常樣本，徹底破壞決策邊界。**最終果斷棄用 SMOTE。**
2. **改採代價敏感學習：**
   * *實作嘗試：* 評估直接設定 `scale_pos_weight = 負樣本數 / 正樣本數`（約 2000~3000）。
   * *實測結果：* 梯度震盪劇烈，模型對邊界極端值過度敏感，收斂困難。
3. **最終解方：平方根阻尼加權（Damped Scale-Pos-Weight） + 閾值截斷：**
   * 取平方根進行加權阻尼（`np.sqrt(neg_count / pos_count)`），將權重控制在 ~50 左右，搭配 LightGBM 樹深限制（max_depth=3~4），有效抑制過擬合並確保數值穩定性。

### Phase 4：模型驗證與可解釋性導入
* 採用嚴格的 **Out-of-Time (OOT) 跨期驗證**，模擬上線後跨季運作的情境，杜絕時間序列上的數據穿越（Data Leakage）。
* 導入 **SHAP (TreeExplainer)**：將前線觸發案件的高貢獻特徵輸出為視覺化條狀圖，作為產出審查工單時的「推薦排查原因」，顯著提升法遵團隊對 AI 模型的採納度。

## 3. 核心工程總結 (Key Engineering Takeaways)

* **業務指標大於數學指標：** 在有固定排查人力的場景下，Top-K 捕獲率比離線 AUC 更具決策指導性。
* **放棄教科書迷思：** SMOTE 等合成過抽樣技術在極端稀疏的真實業務數據中往往弊大於利，損失加權阻尼搭配特徵剪枝更為穩健。
* **可解釋性是落地的敲門磚：** 工程師若無法向業務端解釋「為什麼這個案子被判為異常」，再高的準確率也無法通過內部稽核。
