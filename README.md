# 銀行洗錢防制（AML）異常交易預警系統建置歷程與技術決策

> **2026-04 完成模型開發並上線監控流程使用**  
> 本文為個人工程覆盤筆記，記錄極端不平衡金融數據下的特徵工程、踩坑經驗與指標選型。內容已全數去識別化與脫敏處理。

---

## 1. 專案背景與業務痛點

歷時約一年的開發與驗證，核心瓶頸從來不是單純刷演算法的分數，而是**「極端不平衡數據」**與**「審查人力被海量重複誤報淹沒」**的實務衝突：

* **警示海量且重複觸發，審查量能癱瘓：**  
  傳統規則引擎依賴靜態門檻，每日產生大量合法但踩線的無效 Alert。更棘手的是缺乏歸戶整併，同一客戶在數天內因類似行為連續觸發多筆警示，導致審查員重複開案調閱傳票，70% 以上的工時都在做無效排除。
* **極端稀疏標籤與評估指標失真：**  
  合法交易佔 99.9% 以上，真正經完整調查確認為高風險或申報可疑交易（SAR/STR）的樣本極端稀少（陽性率 < 0.05%）。在這種情境下，傳統 Accuracy 完全無用，未校準的 ROC-AUC 也容易給人模型表現良好的假象。
* **分流結案與法遵可解釋性門檻：**  
  模型如果只追求「抓出異常」，對業務端幫助有限。真正的價值在於建立具備統計信賴度的**低風險分流機制**，讓審查員敢於快速結案；同時每一筆評分都必須有明確的特徵歸因，以通過法遵與內部稽核檢視。

## 2. 端到端實作階段與技術決策

### Phase 1：需求訪談與雙向分流策略
* 與法遵及一線審核員梳理作業流程，確認模型定位為**「風險分層分流機制」**：
  1. **高風險端（優先排查）：** 鎖定最可疑交易（Top-1%），提供關鍵異常特徵依據，加速立案調查。
  2. **低風險端（快速結案）：** 對海量誤報給予穩定低分，輔以安全基準特徵，讓審核員能放心批量或簡易結案。
* **指標定錨：** 放棄全域 ROC-AUC，改以 **PR-AUC**、**Top-K 捕獲率** 以及 **保守覆蓋原則（歷史重大案件零漏報）** 作為核心驗證指標。

### Phase 2：特徵工程與實務資料踩坑
* 使用 SQL 與 Polars 建立多維度時序聚合特徵（1d, 7d, 30d, 360d 交易頻率、金額比值、金流集中度等）。
* **實務踩坑與特徵清洗：**
  * **外匯與交易雜訊：** 初期發現外匯交易金額經常虛增，追查後發現包含境內同名互轉與特定幣轉代號，剔除這些交易雜訊後，特徵才真正反映出異常資金流動。
  * **特徵時效與剪枝：** 初期衍生了 100+ 個特徵，但在跨期驗證（OOT）時發現部分依賴短天期絕對金額的特徵衰退極快。後續改用「長短天期比率」（例如：近 30 天 / 近 360 天金額比值）取代絕對值，並透過 SHAP 值與 PSI 監控進行剪枝，將特徵精煉至數十個最穩定的核心行為特徵。

### Phase 3：LightGBM 模型建置與極端不平衡策略演進
考量百萬級交易資料的推論延遲與表格型資料處理能力，選用以直方圖演算法為基礎的 **LightGBM** 作為基底分類器。在正樣本極端稀少的情況下，經歷了三個調整階段：

1. **嘗試 SMOTE / 過抽樣（大失敗）：**
   * *實作嘗試：* 使用 SMOTE 在少數類別周圍合成虛擬樣本以平衡類別比。
   * *實測結果：* 離線訓練集評分看似提升，但推到跨期測試集時，**False Alarm 暴增近 40%**。
   * *根本原因：* 在高維稀疏空間且陽性樣本極少的情況下，K-NN 插值容易在多數類別的「雜訊邊界」生成錯誤的異常樣本，徹底破壞 LightGBM 樹節點的分裂門檻。**最終果斷棄用 SMOTE。**
2. **改採原生代價敏感學習：**
   * *實作嘗試：* 直接設定 `scale_pos_weight = 負樣本數 / 正樣本數`（數千倍加權）。
   * *實測結果：* 損失函數二階導數（Hessian）震盪劇烈，葉節點權重對極端邊界樣本過度敏感，模型嚴重過擬合。
3. **最終解方：平方根阻尼加權（Damped Scale-Pos-Weight） + 樹結構嚴格約束：**
   * 將加權係數開根號或取對數進行阻尼壓縮（例如取 $\sqrt{\text{scale\_pos\_weight}}$），既保留對少數類的敏感度，又避免梯度劇烈震盪。
   * 搭配限制樹深與葉節點複雜度（嚴格限制 `max_depth`, `num_leaves`, 調大 `min_child_samples`），確保輸出機率平滑，使高分預警與低分快結兩端皆具備統計可信度。

### Phase 4：模型驗證與 SHAP 可解釋性導入
* 採用嚴格的 **Out-of-Time (OOT) 跨期驗證**，以歷史前 10 個月為訓練集、後續數月為 OOT 測試集，嚴禁時間穿越。
* **SHAP 局部特徵歸因：**
  * 導入 `TreeExplainer` 達成毫秒級推論歸因。
  * **高風險案件：** 提取 Top-3 關鍵推力因子，且**只呈現特徵值 > 0 的有效資訊**，直接提供前線作為調查重點提示。
  * **低風險案件：** 驗證其核心行為特徵皆落在常態區間，作為快速結案的佐證。

## 3. 上線成效與實務價值 (Production Impact)

模型經過平行驗證與試營運實測，正式導入日常監控分流機制：

* **審查案件精準收斂逾 90%：**  
  在實測期間，成功將原本人工需逐筆檢視的數百件中/高風險警示案件，大幅聚焦至數十件高嫌疑個體（收斂達 90.45%），實質釋放第一線 70% 以上的無效排查時間。
* **守住「零漏報」合規底線：**  
  在保守門檻設定下，歷史回測與跨期驗證中的所有已知重大可疑交易（SAR）達成 100% 全數捕捉，確保在減量分流的同時不產生任何法遵合規漏洞。
* **推進「歸戶本體」機制：**  
  從業務邏輯層面將多筆分散 Alert 聚合為「顧客本體」，計算該主體的高風險案件佔比，徹底解決長年以來同一個人在短期間內被重複派案、重複開案調查的流程痛點。

## 4. 核心工程總結

1. **模型價值在於「雙向分流」：** 在金融合規調查中，精準篩出「安全案件」以釋放排查人力，與抓出「少數異常案件」同等重要。
2. **放棄教科書迷思：** SMOTE 等合成技術在極端稀疏的真實業務數據中往往弊大於利；合理的損失加權阻尼、嚴格的樹結構約束，搭配乾淨的時序特徵，遠比暴力過抽樣穩健。
3. **可解釋性決定落地生死：** 無法清楚向業務端與法遵解釋「為什麼能判定為低風險而快結」，演算法理論指標再高也無法走出 Jupyter Notebook。
